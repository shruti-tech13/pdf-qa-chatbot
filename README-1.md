# 📄 PDF QA Chatbot

An intelligent PDF Question-Answering chatbot built with **LangChain**,
**Hugging Face**, **FAISS**, and a **Streamlit** UI.

## Features
- Upload and process **multiple PDFs** at once
- Semantic search over document chunks using **FAISS**
- Answers generated by a **Hugging Face LLM** (via Inference Endpoint)
- **Chat history** persisted across turns in the session
- Modular codebase: PDF processing, vector store, and QA chain are separate modules

## Project structure
```
pdf_qa_chatbot/
├── app.py                  # Streamlit UI
├── requirements.txt
├── utils/
│   ├── pdf_processor.py    # PDF loading + chunking
│   ├── vector_store.py     # FAISS embedding + persistence
│   └── qa_chain.py         # Conversational retrieval chain + memory
└── README.md
```

## Setup (local)

1. **Create a virtual environment**
   ```bash
   python -m venv venv
   source venv/bin/activate      # Windows: venv\Scripts\activate
   ```

2. **Install dependencies**
   ```bash
   pip install -r requirements.txt
   ```

3. **Get a Hugging Face API token**
   Create one at https://huggingface.co/settings/tokens (free tier works).

4. **Run the app**
   ```bash
   streamlit run app.py
   ```

5. Open the local URL Streamlit prints (usually `http://localhost:8501`),
   paste your HF token in the sidebar, upload PDFs, click **Process PDFs**,
   and start chatting.

## Notes
- The FAISS index is saved to `./faiss_index` so it can be reloaded without
  re-embedding (see `vector_store.load_vector_store`).
- Swap `DEFAULT_LLM_REPO` in `utils/qa_chain.py` for any other
  Hugging Face chat model you have Inference Endpoint access to.
- To use a fully local, no-API-token setup, swap `HuggingFaceEndpoint`
  for a local pipeline (e.g., `transformers` `pipeline("text-generation", ...)`
  wrapped in `HuggingFacePipeline`) — the rest of the chain is unchanged.
